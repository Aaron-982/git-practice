## Reflection
Throughout the multiple course and personal projects I have done, I've always felt the need to make code compartmentalized and self-explaining, whether that be writing long, descriptive variable names or hiding away complex, single-use blocks of code behind a function. From this article, I find it interesting how it challenges the way I've organized code. 

One example the article brings out is the usage of regexes. To most people, the purpose of a regex won't be immediately clear, and simply wrapping it inside a function doesn't exactly help explain its actual purpose[cite: 3]. I like how the article frames the role of comments in a more collaborative setting, unlike the more personal, individual projects that I've found myself working on as a student. For instance, the author emphasizes that comments are primarily not for the person who made the code, but for future developers looking to change a codebase or a block of code.
